          What do these fields mean?
          

            
IP source / destination. Where the packet claims to come from and where it goes. Leave source blank to use this machine's real address. If you set a source that isn't this machine (spoofing), the packet is sent at layer 2 automatically so the OS can't rewrite the source back to your real IP; for it to arrive, pick the interface that's on the target's network. Destination is required.

            
TTL (time to live). How many router hops the packet may cross before it is dropped. Typical values are 64 (Linux/macOS) and 128 (Windows). Low values can be used for traceroute-style probing.

            
Ports. Source port is usually random and picked by the OS; destination port selects the service (80 HTTP, 443 HTTPS, 22 SSH, 53 DNS, 3389 RDP).

            
TCP flags. Control bits that define the packet's role. SYN opens a connection, ACK acknowledges data, FIN closes gracefully, RST aborts, PSH pushes data to the app immediately, URG marks urgent data. A normal handshake is SYN, then SYN+ACK, then ACK. Odd combinations (all off, or FIN+PSH+URG) are scan techniques.

            
Seq (sequence number). The byte offset of this segment within the TCP stream. For a fresh crafted packet 0 is fine.

            
ICMP type / code. The ICMP message kind. Type 8 code 0 is an echo request (ping); type 0 is the echo reply; type 3 is destination unreachable, with the code giving the reason.

            
Payload. The data bytes after the headers. Text mode sends the characters as-is; Hex mode sends raw bytes you type as hex (for example deadbeef). A single packet is small, so to move a whole file use the Transfer tab instead.

            
Count / interval. How many copies to send and the gap between them in milliseconds.

        this at your own devices or an authorised engagement.
